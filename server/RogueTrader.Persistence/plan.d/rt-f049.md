Parent: [Persistence implementation plan](../IMPLEMENTATION_PLAN.md). November 17, 2026, branch `claude/project-thread-m9yj8x`. The RT-F049 box stays OPEN: this is a slice (see the catalog row).

-   ORIGINAL (emulator `ItmInfo.Item.LoadGeneralSettings1`, `ScriptArena.handlePlayerShop` line 1606, `Commands.cs` ?buy 277 / ?sell 470): f[8] buy 0 = not buyable; f[13] maxAllowed != 0 caps the held quantity at its absolute value, and a shop purchase past the cap is refused whole (never clamped); f[15] sell -1 = cannot be sold, any other value (0 included) pays f[15] per unit; f[10] droppable gates only the voluntary drop (`ScriptArena.cs:728`, `Commands.cs:652`).
-   Implemented: `IPriceSource.TryGetMaxQuantity` + `RejectionReason.MaxAllowedExceeded` in the Buy path (checked before funds); `SellUpgradeAsync` / `SellUpgradeRequest` / `TransactionKind.SellUpgrade` (appended to the enum, so no schema bump: the serializer stores kinds by name and old profiles never contain it) with `UpgradeNotOwned` / `UpgradeNotSellable` refusals; `IPriceSource.TryGetUpgradeSellPrice`; `StationProfileSession.SellUpgradeAsync` and `UpgradeResale`; station JSON carries `sell` (omitted for raw -1), `maxAllowed` and `droppable` per upgrade and `maxAllowed`/`droppable` per good (regenerated with `RT_WRITE_DERIVED_STATION=1`); the Upgrades page has a SELL button per module.
-   Decision, 0-credit sale: legal for installed upgrades and armour (all nine original armours resell for 0; there is no other way to take one off, and the emulator allows it). Cargo keeps the older "sell > 0" rule in `StationPriceTable.FromOriginalItems`, because goods already sell through Trading Outpost recipes and dropping exists for the items with f[10]=1.
-   Fitted armour: armour is an installed upgrade (a set member); the active one per slot is derived, so removing it from the set unfits it in the same saved step and the next best owned item of the slot, if any, becomes active.
-   Not done: voluntary item drop does not exist in the remake, so f[10] is recorded only; ship destruction still empties the hold (Steve's rule; the emulator's death drop follows pruneOdds/pruneDropPercent, not f[10]). Mines (f[13] -10) and weapons/ammo shops are other work. Native verification open.
