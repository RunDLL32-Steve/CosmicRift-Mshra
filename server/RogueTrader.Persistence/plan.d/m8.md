# M8 saved ship condition — Persistence view

Parent: [Persistence implementation plan](../IMPLEMENTATION_PLAN.md). Queue item M8 ([brief](../../../docs/tasks/m8.md)). November 1, 2026.

-   Profile schema **3** adds the optional `ship` condition (`ShipCondition`: hull, x, y, heading; velocity is not saved). Built-in `ProfileSchemaMigrations.V2ToV3` only advances the version, so schema 1 and 2 files load (no ship) and older builds refuse schema 3 as newer instead of quarantining it. Invariants reject non-finite values and negative hull.
-   `ITransactionProcessor.SaveShipConditionAsync` saves it under the same per-profile lock and compare-and-swap, acknowledging only after the save; it writes no ledger or idempotency entry (last write wins) and skips the write when the condition is unchanged.
-   `RejectionReason.NothingToRepair` is returned by the station session, not the core, when a repair would restore nothing.
-   Which fields the original game kept across sessions is unrecoverable (RT-F068), so retaining hull and position is NEW/provisional.
