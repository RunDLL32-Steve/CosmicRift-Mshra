-   Queue C6 (branch `claude/project-thread-shkauf`, master [§13.2 server responsibilities](../../../ROGUE_TRADER_2_PLAN.md#132-server-responsibilities)): new `RogueTrader.Server` library with `AuthoritativeSession`, a headless fixed 60 Hz tick loop (reuses `FixedStepRunner`) and a bounded input queue for one controlled ship. The client only submits `PlayerInput` intent; the session alone advances `WorldSimulation`. NEW/provisional rules: an input names the server tick it is for (first tick 1); only ticks after the last simulated one and at most `MaxInputLeadTicks` (default 60) ahead are accepted; the queue holds at most `InputQueueCapacity` (default 128) inputs; for competing inputs on one tick the highest sequence runs and the rest are superseded, so the result does not depend on arrival order; a tick with no input runs the neutral input; verdicts `Duplicate`, `Late`, `Stale`, `TooFarAhead`, `QueueFull` and `Invalid` (tick 0, non-finite thrust/turn, reserved flags) change nothing. `LastProcessedInputSequence` is the acknowledgement a later snapshot carries. Evidence: `tests/Unit/Server/AuthoritativeSessionTests.cs` (13 tests: 60 Hz advancement and accumulation, queued inputs equal direct ticks by state digest, three arrival orders give one world, late/stale/duplicate, lead and queue bounds, invalid inputs, rejected inputs never change world digest, queue or acknowledgement). Not done: sockets/transport, snapshots, multiple clients, range/rate/teleport policing (C8), any production authority claim. Status: reviewed and merged by Steve in PR 98 (November 2, 2026); no feature checkbox ticked (engineering groundwork, not original parity).
