# Original Rogue Trader feature catalog

Master authority: [ROGUE_TRADER_2_PLAN.md](../../ROGUE_TRADER_2_PLAN.md), §1.2, §§5–10, §§15–16 and §18 exact reproduction gate / M2–M3. Reconciliation: [research plan](IMPLEMENTATION_PLAN.md) and [progress](../development-log/PROGRESS.md). Catalog date: October 14, 2026.

The canonical foundation is [fowlmouth/cosmic-rift-assets at eb1514eaae7f9b9425307d9cc043c74ecdd15e35][canonical]. Original names, values and source bytes remain unchanged. [ASSET_MANIFEST.json](ASSET_MANIFEST.json) pins their identities. The raw index produced by `scripts/index-original-content.py` retains record rows, raw tokens and complete records; this catalog names acceptance work rather than replacing that data. The active package selects `ITM/Rogue_mp.itm` in `CFG/rogue.cfg` row 7. The alternative `ITM/Rogue.itm` is not silently substituted.

Original gameplay and native presentation features remain **unchecked**. Narrow completed archive/decoder/export capabilities carry explicit tested scope below; they cannot complete a whole hull, weapon or world feature. Source discovery, successful indexing, decoded pictures and the provisional flight prototype do not demonstrate exact original gameplay. Stable IDs must not be renumbered or reused when new features are discovered.

`V` means VERIFIED contents of an actually read preserved source, not verified original executable behavior. `V/N` additionally marks dated news/help statements that conflict with another revision. `R` means RECONSTRUCTED interpretation or display mapping, explicitly awaiting validation. Raw field indexes `f[n]` are zero-based; source rows are one-based. Missing semantics are recorded as pending interpretation, rather than missing original values. Original reference [field contracts](FIELD_INTERPRETATION.md) keep operational hypotheses separate.

The acceptance profiles used by the content tables are:

| Profile | Required acceptance before checking off the feature |
|---|---|
| HULL | Resolve RPG skill → VEH ID → original sprite/effect/sound records; validate all hull, energy, movement, cargo, terrain, installation and starting-loadout fields; render original directions/poses; verify the completed hull's behavior against the selected revision. A ship-selection label or a sprite alone is insufficient. |
| RESOURCE | Preserve item identity/category/raw mass; resolve original icon/physical pickup, spawn/drop/refine/trade recipes and prices; verify the completed resource's inventory and economic lifecycle. |
| ITEM | Resolve the full versioned record, skill/category/quantity restrictions and every child/ammo/vehicle/blob reference; preserve raw purchase/resale/use values; validate original effect, timing, interactions and presentation where applicable. An invisible child effect may require its parent feature's acceptance. |
| ACTOR | Resolve the full VEH computer record, production/trading/repair/combat/event dependencies, original graphics/audio, faction/ownership and spawn/respawn rules; verify its completed original role. |
| OBJECT | Resolve complete LIO record and referenced world/actor/item/warp/sound IDs; place it at original coordinates; validate the completed event's area, timing, conditions and actions. Static decorative records need byte/pixel/layout checks, not gameplay simulations. |

`F` targets the mandatory master exact reproduction gate before invented expansion. `M2` supplies the original core loop; `M3` adds its shared multiplayer execution. These labels are dependency targets, not authorization to start every feature simultaneously. Current owners identify repository modules; **unassigned** means no agent has yet accepted implementation responsibility. Gameplay simulation is run only after that specific feature is implemented and needs behavior verification. Research uses source, parser, hash and image checks.

Unchecked entries default to **Not started for exact runtime implementation** unless the active-status table below says otherwise. Parsed source availability is research evidence, not a runtime-status promotion. Update this table and the relevant scoped plan as an entry moves through Investigation, In progress, Testing and Done. Completed entries leave the active queue and remain in the checked catalog/master audit with concise evidence/history.
