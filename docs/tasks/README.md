# Actionable task briefs

[TASK_QUEUE.md](../../TASK_QUEUE.md) is the ordered index and status snapshot; [ROGUE_TRADER_2_PLAN.md §18](../../ROGUE_TRADER_2_PLAN.md#18-development-roadmap) remains the master scope/status authority. Read the selected brief before claiming work. Queue IDs are not feature completion claims.

Active briefs are one file per active queue item: G1, G5, G6, G8–G10, M5, M7–M9 and C1, C4, C6–C10. Completed rows were removed from the active tables and retained as concise history in the queue. [M3](m3.md) records the merged generic mining slice and its remaining original-parity limits.

Each brief records its status/dependencies, master location, existing files with key types/methods, exact relevant tests, a bounded next change, acceptance, focused checks, model/effort, and original-parity limits. Before starting, verify current main, dependencies, branches, owner claims and PRs; the queue’s historical notes are not live status. Follow [AGENTS.md](../../AGENTS.md) for branch, push, review and merge permissions.

Use [TEMPLATE.md](TEMPLATE.md) when adding or revising a brief. Do not drop master/catalog scope to make a brief smaller, and do not create additional scope, IDs, or completion claims through a brief.
