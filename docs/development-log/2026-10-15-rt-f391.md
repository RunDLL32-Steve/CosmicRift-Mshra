# RT-F391 optional admin-prize whitelist — October 15, 2026

Read-only source investigation of the pinned upstream (no derived or canonical file changed).

-   `Arena.initLists()` (`ZoneServer/Game/Arena/Arena.cs`, called from arena init) loads `Assets/PrizeItems.xml` if present into `_prizeItems` and sets `Prizelist = true`; if absent it prints "File not found" and sets `Prizelist = false`.
-   The only consumer is the moderator prize command in `ZoneServer/Game/Commands/Mod/Basic.cs`: for the lowest granted moderator level (`PlayerPermission.Level1`), an item with `buyPrice == 0` can be prized only if its ID is on the list; with no list the moderator is told "Prize item list does not exist, please contact admin" and the command is refused. Higher levels and purchasable items are unaffected.
-   Nothing in player gameplay, the shop, the arena script path or Rogue Trader resources reads it, and the original Rogue Trader package defines no such file.

Decision: this is an optional administrator-policy feature, not an original Rogue Trader resource. Its absence is intentional fail-closed behavior for one moderator command. No file, stub or code change is created. A whitelist should be authored only if a granted-moderator prize workflow is later wanted.

Same-day related decision: a skill-shop location gate (terrain `SkillEnabled`) was considered and rejected. `CfgInfo.Terrain.skillEnabled` is parsed but never read by the pinned server, so unlike `StoreEnabled` (enforced by `/buy` and `/sell`, now applied to packet shops under RT-F389) there is no original server rule to restore.
