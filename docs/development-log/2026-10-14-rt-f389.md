# RT-F389 store location gate — October 14, 2026

Branch `fix/rt-f389-store-proximity`. Pinned upstream `Handle_CS_Shop` forwards every packet to `ScriptArena.handlePlayerShop` with no location check, while the original `/buy` and `/sell` chat commands only proceed on `StoreEnabled` terrain or for a spectator when `SpectatorStore` is set. A client could therefore buy or sell anywhere.

Fix (derived only, [shop-store-access.ps1](../../scripts/compatibility/patches/shop-store-access.ps1)): `canUseStore` applies that same rule and fails closed on missing state or out-of-range positions; the guard runs before price, inventory, cash and script-hook side effects. Canonical files and upstream references are unchanged.

Evidence: 11 new Store.\* checks through the actual handler with NEW in-memory map/terrain fixtures. Before the patch 8 fail (sell and buy outside a store, hook invoked, boundary, out-of-range, spectator flag misuse, missing state); after it all 61 runtime checks pass, native delivery fixed checks still pass and `verify.ps1` passes (41/41 unit tests, Godot smoke). The wrapper scripts print a spurious exit failure under Windows PowerShell 5.1; the JSON reports and stdout logs are authoritative.

Open: the skill shop (`handlePlayerShopSkill`, terrain `skillEnabled`) has no location check; durable transactions; native store UI.
