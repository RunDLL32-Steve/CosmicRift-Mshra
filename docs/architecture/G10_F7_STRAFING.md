## Proposed bounded local behavior

1. Add optional trailing `float Strafe = 0` to `ShipInput` to preserve existing constructor calls. Finite values clamp to [-1,1], nonfinite become 0 like existing axes. Negative means left; positive right. Input capture uses opposing actions, so simultaneous left/right yields zero. Include actions in settings, remap UI and HUD.
2. `ShipPhysics.StrafeThrust` is a nonnegative force, default 0 for existing catalogs/JSON. Validate finite and nonnegative on catalog load. Derive per hull from the specific raw block via `EmulatorFlightReading`, multiplied by `OriginalShipPhysics.Mass`; regenerate derived external JSON and compare every hull with its own source. Do not overwrite raw files or flatten the other hull attributes. Open-space initial slice works before terrain selection exists. Once terrain profiles land, each selected `ShipPhysics` includes its own strafe force. Unknown/inactive terrain policy belongs to F12 and must not silently substitute an invented original value.
3. In the existing 60 Hz `ShipMotion` shared by world and motion adapter: select the start-of-tick terrain profile when available; sanitize axes; rotate; evaluate existing boost eligibility/energy; compute longitudinal and lateral impulses from the updated heading. With `forward=(cos h,sin h)`, `right=(-sin h,cos h)`, add `right * strafe * StrafeThrust / mass * dt`; left is its negative. Sum independent forces without diagonal normalization, following bot evidence as a provisional choice; then terrain drag if available, magnitude cap, and existing swept collision. Do not change zero-strafe arithmetic/order in the legacy path: float bit patterns feed replay hashes. Position, velocity and heading remain simulation authority.
4. NEW/provisional interaction: boost still requires nonzero longitudinal input and a full tick of energy, and changes only longitudinal thrust and max speed. Side thrust uses normal selected strafe force, including while boost is engaged; strafe alone does not spend boost energy. Clamp the combined resulting velocity once to the selected normal/hyper speed; coasting preserves momentum absent terrain drag/collision. Reverse uses the existing owner-approved -1 fallback; no new sentinel interpretation. Expose unresolved native rules as such.

## Compatibility boundaries

`SimulationRecording` v3 has exactly 10 bytes/input (two floats, fire byte, flag byte), reads v2 and v3, and cannot encode analog strafe. Introduce v4 with a third float and version-specific input size; continue reading both v2 and v3 as strafe zero, retain strict flag/count/truncation/trailing-byte checks, and record full float without quantization. Test old bytes and checkpoint/final hashes against same catalog and runtime/hardware. `WorldStateHasher` hashes state floats bitwise, not inputs or catalog; no extra hash field is needed for an axis, but changed world physics or catalogs can legitimately invalidate old hashes. Replay never embeds the catalog; no blanket compatibility claim across changed terrain/catalog physics.

C6 `PlayerInput` and codec v1 carry thrust/turn/fire only; C7 `ShipPredictor` stores and replays that exact type. Both map to `ShipInput` with strafe zero. Preserve their API, wire bytes, validation, and zero-axis predictions/authority tests; local strafe is deliberately not represented over this provisional protocol. Do not add a protocol version or claim multiplayer support in this slice. A future explicit coordinated protocol/predictor/authority change must represent and validate the axis end-to-end, including corrections; never silently drop a claimed network strafe.
