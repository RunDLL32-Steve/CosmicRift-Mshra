# M9 first playable progression loop — client view

Parent: [Client UI implementation plan](../IMPLEMENTATION_PLAN.md). Queue items M7 (kill reward slice) and M9 in [TASK_QUEUE.md](../../../TASK_QUEUE.md); briefs [M7](../../../docs/tasks/m7.md) and [M9](../../../docs/tasks/m9.md). November 1, 2026.

-   **Loop.** Fly, destroy practice targets for credits, collect cargo, dock at the Trading Outpost to trade it, then repair and buy upgrades; quitting and relaunching restores wallet, cargo, upgrades, hull and position. Every number not taken from the originals is labelled NEW in its data file.
-   **Kill rewards.** `WorldSimulation.Kills` records each target destruction once. `GameClient` queues each player kill and pays it through `StationProfileSession.GrantKillRewardAsync`, whose transaction id is stable per sector instance and target (`kill-<instance>-<target>`), so retries after a refusal or a lost acknowledgement are duplicates and pay once. A refused grant stays queued and retries once a second (the profile is reloaded after a save failure). The HUD shows the reward in a short notice under the cargo line. Leaving a sector (reset or relaunch) gives queued kills one last try and reports any that were lost.
-   **Reload warning (M8 review follow-up).** Reloading or reopening the profile computes the hold units the saved profile does not hold (`StationProfileSession.UncommittedPickups`) before reconciling the hold, and reports them in the pause-menu status and as a HUD notice: "Reload discarded N unsaved cargo units collected since the last save (...)". Superseded by the queue M7 mining slice: pickups are now granted one by one with stable per-world ids and stay queued across a reload, so a reload discards nothing and this warning was removed.
-   **Verification.** `ClientStationSmokeTest` now destroys the target ahead of the spawn with the native fire key, checks the wallet rises by the configured reward, that a replay of the same kill is a duplicate and that the HUD shows it; later it places unsaved cargo in the hold while paused and checks the reload drops it and says so. The engine-level exit/relaunch acceptance is [`tests/Integration`](../../../tests/Integration/IMPLEMENTATION_PLAN.md).
-   **Target respawn (follow-up, November 1, 2026).** When the whole target group is destroyed, `WorldSimulation` respawns it after the sector's `targetRespawnSeconds` (60 s, NEW) as the next wave; kills carry the wave, so each wave pays once. The HUD counts down to the next group. A sector reset (`R`) now carries the target group into the rebuilt world (`WorldSimulation.CarryTargetsFrom`) and keeps the sector instance id, so destroyed targets stay down until the timer runs out and resetting no longer re-arms kill rewards; queued kills survive the reset. Relaunching still starts a fresh group, because target state is not saved. Piles still refill on a reset (unchanged).
-   **Not done.** Original NPCs, drops, death/respawn policy, mining in the client (the M3 engine still uses a fixture; no original refining flow), native HUD/flow. No original feature box or count changes.
