# Sector map overlay (M) — client view

Parent: [Client UI implementation plan](../IMPLEMENTATION_PLAN.md). Steve's ask (November 4, 2026): "Pushing 'M' should show the user the map, and where they are on it live as they are moving. It should be zoomable as well in and out." Stacked on the G10 F10 full-size map (claude/project-thread-h9uu0u, PR #118).

-   **View.** `SectorMapOverlay` (a full-screen `Control` on the HUD layer) draws the derived Rogue map one texture pixel per tile (walls, store/trade/repair zones), the team stores, Trading Posts, Repair Docks and refinery with their dock rings, drops and live practice targets, and the player's ship arrow, every frame from the same `WorldSimulation` the radar reads. NEW: the original map screen, if any, is unknown (G10 H3).
-   **Zoom and pan.** Zoom 1 fits the whole map; each step (wheel, + / -, PageUp / PageDown) multiplies by 1.25 up to 12 screen pixels per tile. The view follows the ship (clamped so the map never leaves the screen); a drag pans and stops following, double-click or Home follows again, and zooming fully out follows again.
-   **Input.** New rebindable action `sector_map` (default M) in `FlightInput.Bindings`. While the map is open, `GameClient` takes only M, Escape, the zoom keys and Home; flight keys still reach the ship. Opening the pause menu, the inspector, a station screen or the ship picker closes the map. The practice sector (no map) shows a notice instead.
-   **No cheating.** Display only: no server, simulation or prediction change, and nothing beyond the radar's information (no other players).
-   **Verification.** `ClientInputSmokeTest` opens the map with M, checks the world keeps ticking and the ship moves under it, zooms in and out to both limits, and closes it with Escape (not pausing) and with M. Rendered captures (`--capture-map`, `--capture-map-zoom=N`) checked under Xvfb. No RT-F box ticked.
