## Implemented

- New project `RogueTrader.Protocol` (net8.0, pure C#, no packages, no sockets, no Godot, no reflection).
- Frame: `[version u8 = 1][type u8][payload length u32][payload]`, little-endian, float32 IEEE-754. Frame must equal header + declared payload exactly.
- Messages: `PlayerInput`, `WorldSnapshot` (+ `EntityState`), `TransactionRequest`, `TransactionResponse`. Requests carry only item id + quantity + idempotency key; no price, currency, damage or item grants (plan 13.5).
- `MessageCodec.TryDecode` is total and never throws; failures are a `ProtocolError` (Truncated, UnsupportedVersion, UnknownMessageType, PayloadTooLarge, TrailingBytes, NonFiniteValue, InvalidEnumValue, InvalidFlags, TooManyEntities, StringTooLong, InvalidString, InvalidArgument). Throwing wrappers raise only `ProtocolException`.
- Allocation is bounded: payload length and entity counts are checked against limits and against the bytes actually present before any array is allocated.
- Accepted frames are canonical (decode then encode reproduces the same bytes).

## NEW / provisional values (not original data, not tuned)

Version 1, header 6 bytes, `MaxPayloadBytes` 65535, `MaxSnapshotEntities` 512, `MaxItemIdBytes` 64, entity wire size 33 bytes, `InputFlags.Fire` bit, entity/transaction enum members, and world units/rotation radians. These are not original Rogue units; original unit/sentinel semantics stay open (see the module plan).

## Not verified / not done

- No network transport, handshake/authentication, fragmentation, sequence/ack windows, compression or encryption (later M3 work; C6-C8 depend on this).
- Fuzz is a fixed-seed deterministic sample, not coverage-guided fuzzing.
- Wire format is not yet reviewed by an independent agent; field set (snapshot entity fields, transaction kinds) is a provisional proposal.
- Unit-test project now references the Protocol project; `scripts/verify.ps1` and Godot smoke were not run (client unchanged).
